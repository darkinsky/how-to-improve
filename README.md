# How to Improve

一个关于“如何持续改进”的知识库与实践仓库。

这个仓库用于沉淀工程、科研和个人成长中的方法论、实验记录、复盘和可复用模板。目标不是收集鸡汤，而是形成一套可以持续迭代的改进系统：观察问题、提出假设、设计行动、记录结果、复盘优化。

## 目录结构

```text
.

│   ├── engineering/   # 工程实践、效率工具、代码质量、架构思考
│   ├── research/      # 科研方法、论文阅读、实验设计、写作积累

│   └── roadmap.md     # 仓库建设路线图

```

## 核心循环

1. **Observe / 观察**：发现问题、瓶颈或可提升点。
2. **Measure / 度量**：明确现状，用事实和数据描述问题。
3. **Hypothesize / 假设**：提出一个可验证的改进假设。
4. **Act / 行动**：做一个足够小、能快速验证的实验。
5. **Reflect / 复盘**：记录结果，保留有效做法，淘汰无效做法。
6. **Iterate / 迭代**：把经验沉淀为流程、模板或原则。

## 推荐记录格式

每个改进条目尽量回答这几个问题：

- 我想改进什么？
- 当前状态是什么？
- 我打算尝试什么？
- 如何判断有效？
- 实际结果如何？
- 下次怎么做？

可以从 [`docs/notes/improvement-note-template.md`](docs/notes/improvement-note-template.md) 开始。

## 初始方向

- 工程效率：开发流程、调试、代码审查、自动化、知识管理。
- 科研能力：论文阅读、问题定义、实验设计、写作表达。
- 复盘系统：周复盘、项目复盘、失败案例库。
