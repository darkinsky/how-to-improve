# Debugging Playbook

## 先看结论

调试不是随机试错，而是用证据快速缩小问题空间：

```text
复现 → 定界 → 假设 → 观察 → 修复 → 回归 → 复盘
```

目标是留下可复用的证据链，而不是只留下“最后改了哪一行”。

---

## 标准流程

1. **确认现象**：错误信息、影响范围、首次出现时间、是否可稳定复现。
2. **建立最小复现**：最小输入、最小环境、最少依赖。
3. **定界问题层级**：输入、配置、代码、依赖、数据、网络、资源、权限、外部服务。
4. **写假设树**：每个假设都要有可验证信号。
5. **一次只改一个变量**：避免把修复和偶然恢复混在一起。
6. **补回归测试**：能自动验证的问题不要只靠人工记忆。
7. **写复盘**：记录根因、触发条件、检测方式、预防措施。

---

## 快速检查清单

| 方向 | 问题 |
|------|------|
| 输入 | 输入数据、参数、边界值是否变化？ |
| 环境 | OS、依赖版本、镜像、环境变量是否变化？ |
| 状态 | 缓存、数据库、队列、文件系统是否残留旧状态？ |
| 并发 | 是否存在 race condition、锁、重试、超时？ |
| 资源 | CPU、内存、磁盘、GPU、连接池是否耗尽？ |
| 权限 | token、scope、文件权限、网络 ACL 是否变化？ |
| 时间 | 时区、clock skew、过期时间、定时任务是否相关？ |
