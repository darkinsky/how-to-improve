# Study Materials 内容标准

## 文档元信息

| 字段 | 内容 |
|------|------|
| 主题领域 | Study Materials |
| 材料类型 | 标准 / 模板 |
| 难度 | 入门 |
| 优先级 | P0 / Survey |
| 状态 | 推荐 |
| 建议用途 | 统一学习资料的选材、结构、标签和维护标准 |

---

> **用途**：统一本目录下学习资料的选材标准、文档结构、优先级标签和维护方式。  
> **原则**：少而精、可执行、可更新；优先保留能形成长期能力的课程、论文、代码和项目。

---

## 1. 选材原则

### 1.1 优先收录什么

优先级从高到低：

1. **经典基础**：长期有效、被广泛教学或工业实践验证的课程、教材、论文。
2. **范式代表**：开创一类方法、系统或工程模式的论文 / 项目。
3. **前沿系统**：能代表当前研究或工业方向的开源系统、技术报告、benchmark。
4. **可复现材料**：有代码、实验、作业、Lab、tutorial 或清晰实现路径的资料。
5. **高质量综述**：能帮助建立知识地图，而不是只罗列链接的文章。

### 1.2 谨慎收录什么

- 只有标题党结论、没有技术细节的博客。
- 短期热点但缺少复现、缺少引用、缺少系统价值的材料。
- 内容重复但质量不如已有条目的链接。
- 需要登录、付费、内网或非公开访问的资料。

---

## 2. 优先级标签

| 标签 | 含义 | 使用场景 |
|------|------|----------|
| `P0` | 必读核心 | 方向入门或长期能力建设不可跳过 |
| `P1` | 强烈推荐 | 重要补充，适合完成主线后深入 |
| `P2` | 选择性阅读 | 有价值但依赖具体方向或兴趣 |
| `Frontier` | 前沿跟进 | 近年论文、系统、benchmark、技术报告 |
| `Classic` | 经典材料 | 长期稳定、基础性强 |
| `Hands-on` | 实践优先 | 有 Lab、项目、代码或可复现实验 |
| `Survey` | 综述 / 地图 | 用于建立全局理解 |

建议每篇文档至少给出：

- **优先级**：`P0 / P1 / P2`
- **材料类型**：课程 / 论文 / 系统 / 实践 / 综述 / 索引
- **难度**：入门 / 中级 / 进阶 / 前沿
- **状态**：草稿 / 可用 / 推荐 / 需更新

---

## 3. 推荐文档结构

新增或大改文档时，优先使用以下结构：

```markdown
# 主题名称

## 文档元信息

| 字段 | 内容 |
|------|------|
| 主题领域 | AI Infra / Agent / RL / Generative Models / CS / ... |
| 材料类型 | 课程 / 论文 / 系统 / 实践 / 综述 / 索引 |
| 难度 | 入门 / 中级 / 进阶 / 前沿 |
| 优先级 | P0 / P1 / P2 / Frontier / Classic / Hands-on |
| 状态 | 草稿 / 可用 / 推荐 / 需更新 |
| 建议用途 | 入门主线 / 深入专题 / 实践项目 / 前沿跟进 |

---

## 先看结论

用 5-10 条 bullet 讲清楚：这个主题为什么重要、核心矛盾是什么、该先学什么。

## 知识地图

用图、表或层级结构建立全局理解。

## 必读 Top 10

只放最重要的课程、论文、系统或代码，避免无限堆链接。

## 学习路线

按 1 周 / 1 月 / 3 月，或基础 → 进阶 → 前沿组织。

## 实践项目 / 完成标准

给出可验证输出，例如复现论文、读源码、实现 mini system、跑 benchmark。

## 最新进展

只记录方向性变化、代表系统和重要论文，不追逐所有新闻。

## 延伸资料

放 P1 / P2 材料，并说明为什么值得看。
```

---

## 4. Top 10 选择标准

每个主题的 `Top 10` 应满足：

1. 能覆盖该方向的关键概念，而不是十个相似链接。
2. 至少包含一项可实践材料：课程 Lab、开源系统、复现实验或工程项目。
3. 至少区分经典基础与前沿趋势。
4. 每个条目最好附一句“为什么重要”。
5. 宁可少于 10 个，也不要为了凑数降低质量。

---

## 5. 前沿内容维护标准

前沿文档更新时，优先回答三件事：

1. **新问题**：它解决了旧方法的什么瓶颈？
2. **新范式**：它是否改变了系统设计、训练范式、评测方式或工程流程？
3. **可迁移性**：它对实际项目、源码阅读或研究选题有什么启发？

不建议只按时间顺序堆论文。更好的组织方式是：

- 按问题分类：训练 / 推理 / memory / benchmark / safety；
- 按系统层级分类：kernel / runtime / scheduler / storage / evaluation；
- 按范式分类：RLHF / RLVR / agentic RL / inference-time search。

---

## 6. 维护检查清单

每次新增或大改文档后，检查：

- [ ] 是否有清晰的“先看结论”？
- [ ] 是否有元信息：主题、难度、优先级、状态？
- [ ] 是否区分 P0 / P1 / P2？
- [ ] 是否包含实践项目或完成标准？
- [ ] 是否避免重复链接和低质量链接？
- [ ] 相对链接是否可点击？
- [ ] 前沿材料是否说明“为什么重要”，而不是只列标题？
